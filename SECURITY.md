# Security Policy

## Project status

Proyecto publicado con fines de desarrollo o demostración. Esta publicación no garantiza preparación para producción ni autorización para utilizar sistemas o datos de terceros.

## Reporting a vulnerability

Please **do not open a public issue containing secrets, exploit details, personal information or customer data**.

Use GitHub's **Report a vulnerability** private reporting feature if available under this repository's Security tab. If it is not available, contact the maintainers privately through an established channel. Do not post sensitive evidence publicly.

Please include a concise description, affected version and a minimal reproduction based **only on your own test data**. Do not scan live services, customer environments or third-party systems without separate written authorization.

## Data and credentials

- Never submit real credentials, environment files, database dumps, backups, personal records or customer-owned source code.
- Use synthetic data and local, isolated environments.
- Do not treat examples, proofs of concept or documentation as permission to access production.
- Security changes require review and validation; publishing this policy does not mean the project has passed a security audit.

## Responsible disclosure

Maintainers will assess reports, coordinate remediation where appropriate and decide whether a public advisory is needed.
